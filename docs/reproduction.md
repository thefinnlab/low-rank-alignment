# Reproducing the paper results

Run these stages in order from the repository root. Commands below run locally
and sequentially; they do not submit Slurm jobs. They cover all seven model
families, all three datasets, all six directed transfers, and the configured
word-label offsets. Existing analysis settings and artifact identities are
taken from the checked-in configs.

This is the complete execution order, but a fresh checkout still requires
externally supplied data and annotation resources listed in steps 2–3. The
repository does not yet provide every download, original preprocessing step,
or a pinned release/checksum for every external input.

## 1. Install the environment

Use Python 3.12 and install the locked dependencies:

```bash
uv sync --frozen
export PYTHONPATH="$PWD"
export PAPER_MODELS="gpt2 gpt2-xl gpt-j-6b llama3-8b roberta-large random-gpt2 glove"
export PAPER_DATASETS="podcast cars-2 fmri"
```

Keep these variables in the shell used for subsequent commands. The lockfile
selects CUDA 13.0 PyTorch packages; the embedding configs select CUDA. Use a
compatible GPU environment. Dataset downloads additionally require Git,
curl, unzip, jq, DataLad, and git-annex. Install these system tools separately.

## 2. Supply the datasets and GloVe vectors

| Input | Required location and contents |
| --- | --- |
| Podcast recordings | `data/derivatives/ecogprep/sub-01/ieeg/` through `sub-09/ieeg/`, containing the preprocessed BIDS FIF recordings and channel metadata. Epoch generation requests high-gamma recordings. Original acquisition-to-FIF preprocessing is outside this repository. |
| Podcast transcript | `data/stimuli/podcast_transcript.csv`, with word text and start/end timings used by embedding generation. |
| Podcast audio | `data/stimuli/podcast.wav`, needed for diarization and intensity labels. |
| Podcast annotations | `processed_data/df_word_onset_with_pos_class.csv` and `processed_data/iu_boundaries.csv`, aligned to the canonical transcript. These supplied annotations are not generated by the retained scripts. |
| Brain Treebank | `data/brain-treebank/`, including recordings and the shared metadata, timing, transcript, electrode, and native-label archives. The analysis cohort is Cars 2 subjects 3, 7, and 10. |
| fMRI toolbox | `data/deep-fMRI-dataset/`, including `encoding/ridge_utils/` and `em_data/sess_to_story.json`. |
| fMRI dataset | Under that toolbox, `data/ds003020/derivatives/`, including `TextGrids/`, `respdict.json`, and `preprocessed_data/<subject>/<story>.hf5`; audio belongs in `data/ds003020/stimuli/<story>.wav`. Configs select sessions 1–5 and subjects UTS01–UTS09. |
| GloVe | `data/glove/glove.6B.300d.txt`. All models use its vocabulary filter; it is required even when a transformer model is being analyzed. Cars 2 falls back to this parent data directory. |

The repository automates the Brain Treebank download:

```bash
bash scripts/download_brain_treebank.sh --data-root data/brain-treebank
```

The downloader selects subjects with at least two movies and downloads their
trials; its scope is broader than the Cars 2 analysis cohort. The command is
resumable. It does not generate Podcast or fMRI inputs.

For fMRI, obtain the toolbox and dataset at the paths above. For a fresh data
checkout, the following commands make the required layout explicit:

```bash
git clone https://github.com/HuthLab/deep-fMRI-dataset.git data/deep-fMRI-dataset
datalad clone https://github.com/OpenNeuroDatasets/ds003020.git data/deep-fMRI-dataset/data/ds003020
datalad -C data/deep-fMRI-dataset/data/ds003020 get derivatives stimuli
```

Skip cloning directories that already exist. Record toolbox and dataset commit
IDs with the submission; the repository does not currently pin those checkouts.
Verify that every configured subject/story response exists before fitting.
Podcast acquisition/download instructions remain to be supplied by the authors.

## 3. Cache models and stage annotation resources

The embedding configs load local snapshots, not online model names. Set
`HF_TOKEN` in the environment if required by your model access, then run:

```bash
uv run python -m scripts.utilities.cache_pipeline_models
```

This populates `model_cache/models/` for GPT-2, GPT-2 XL, GPT-J, Llama,
and RoBERTa. Random GPT-2 reuses the GPT-2 architecture/tokenizer with the
configured initialization seed; GloVe requires no transformer snapshot.
The config key `llama3-8b` currently uses the Llama-3.1-8B snapshot.

Place the following author-supplied tables under `data/language_resources/`:
`concreteness.csv`, `lancaster.csv`, `nrc-vad-v2.tsv`,
`age-of-acquisition.csv`, `word-prevalence.csv`, `semantic-diversity.csv`,
`socialness.csv`, and `swow.csv`. Required column names and separators are in
`configs/language_features/podcast.yml`. Use the releases used for the paper;
their sources, release IDs, and checksums still need to be recorded. Staging
does not download files marked `manual: true`.

Stage the configured language models, parsers, and corpora after supplying
those files and obtaining access to the diarization model:

```bash
uv run python -m scripts.utilities.generate_language_features \
  --config configs/language_features/podcast.yml --stage-resources
uv run python -m scripts.utilities.generate_language_features \
  --config configs/language_features/brain_treebank.yml --stage-resources
uv run python -m scripts.utilities.generate_language_features \
  --config configs/language_features/fmri.yml --stage-resources
```

Staging includes separate annotation copies of GPT-2/RoBERTa, Stanza,
WordNet, and pyannote resources. It does not reuse every embedding snapshot.

The fMRI boundary generator also needs a local PSST model and tokenizer.
Its current default is
`foundation_model_weights/models--NathanRoll--psst-medium-en/snapshots/a1112ed5890f654737cfe71eb27bffd8e1ffe363`.
Supply that checkpoint or pass its equivalent local directory with
`--psst-model PATH`. Segment Any Text uses `sat-3l` with
`ted2020-corrupted` style; its resources must be accessible/cached when the
boundary command runs. These resources are outside the language-resource
staging command. Audio generation also needs a working audio-decoding backend.

## 4. Generate contextual embeddings

Generate Podcast embeddings, explicitly selecting its dataset because the
shared random-GPT-2 config currently declares `deep-fmri`:

```bash
for config in configs/embeddings/*.yml; do
  uv run python -m scripts.utilities.generate_embeddings \
    --config "$config" --dataset=podcast
done
```

Generate Cars 2 embeddings directly from its configs. This avoids the broader
multi-movie sweep in `generate_brain_treebank_embeddings.py`:

```bash
for config in configs/brain_treebank/cars_2/generate_*.yml; do
  uv run python -m scripts.utilities.generate_embeddings --config "$config"
done
```

Generate fMRI story embeddings using the same six contextual-model configs:

```bash
for config in configs/embeddings/*.yml; do
  uv run python -m scripts.fmri.generate_pipeline_embeddings --config "$config"
done
```

The fMRI template supplies paths, sessions, and subjects; each flat config
supplies the complete model/layer grid. GloVe vectors are loaded at analysis
time. Contextual outputs contain `features.hdf5`, `transcript.tsv`, and
`metadata.json`. GPT-2 XL is named `gpt2-xl-batch` in generated outputs.
Embedding generation overwrites output files; do not run it concurrently
against the same model/dataset directory.

On a fresh checkout, also create the Podcast compatibility alias used by the
preprocessing and feature configs:

```bash
ln -s gpt2-xl-batch data/stimuli/gpt2-xl
```

If `data/stimuli/gpt2-xl` already exists, verify that it contains the same
canonical transcript and embeddings instead of replacing it. The analysis
configs use `gpt2-xl-batch`; some preparation configs still use `gpt2-xl`.

## 5. Generate iEEG epoch caches

```bash
uv run python -m scripts.utilities.precompute_epochs \
  --config configs/precompute_epochs/precompute_epochs_default.yml \
  --high-gamma-channel-batch-size 8
uv run python -m scripts.utilities.precompute_epochs \
  --config configs/brain_treebank/cars_2/precompute_epochs.yml \
  --high-gamma-channel-batch-size 8
```

Epochs are shared across models; generate them once per iEEG dataset. The
explicit channel batch is needed because the current CLI compares its optional
default (`None`) to an integer. The batch size bounds temporary memory and
does not select a different analysis. fMRI loads the supplied preprocessed
responses directly and does not use this epoch-generation stage.

## 6. Generate language labels

First generate fMRI sentence and IU boundaries, then the base feature artifacts:

```bash
uv run python -m scripts.utilities.generate_fmri_language_boundaries
for config in podcast brain_treebank fmri; do
  uv run python -m scripts.utilities.generate_language_features \
    --config "configs/language_features/$config.yml"
done
```

The boundary generator defaults to all available TextGrids; feature generation
uses the story list in the fMRI feature config. Generation enables the provider
sets already declared in each config and writes canonical `tokens.tsv` and
provenance manifests under `processed_data/language_features/`.

Add the recurrence labels and audio intensity used by the decoding manifests:

```bash
uv run python -m scripts.utilities.generate_recurrence_features \
  --config configs/language_features/podcast.yml \
  --config configs/language_features/brain_treebank.yml \
  --config configs/language_features/fmri.yml
uv run python -m scripts.utilities.generate_audio_intensity \
  --config configs/language_features/podcast.yml \
  --config configs/language_features/fmri.yml
```

Cars 2 uses its native intensity RMS. The focused surprisal, Cars 2
concreteness, fMRI interpretable-feature, and fMRI IU scripts update selected
columns without rerunning the full provider set; they are optional repair/update
tools after full generation, rather than additional mandatory fresh-run stages.
Run focused updates after base generation so a later full generation does not
replace their output.

## 7. Run significance for the complete model/layer union

```bash
for dataset in $PAPER_DATASETS; do
  make significance DATASET="$dataset" MODELS="$PAPER_MODELS" CMD="uv run python"
done
uv run python -m scripts.utilities.check_final_significance \
  --results-root results --models $PAPER_MODELS
```

Complete this stage for all selected models and layers before RRR: the retained
RRR configs select the union of significant targets across the seven families.
Do not override the union to make a partial run appear complete.

## 8. Run internal RRR and transferable source fits

```bash
for dataset in $PAPER_DATASETS; do
  make rrr DATASET="$dataset" RRR_MODE=cross_model_layer \
    MODELS="$PAPER_MODELS" CMD="uv run python"
done
for dataset in podcast cars-2; do
  make rrr DATASET="$dataset" RRR_MODE=full_fit \
    MODELS="$PAPER_MODELS" CMD="uv run python"
done
```

Internal RRR produces rank-evaluation results and the configured PCA baselines.
The iEEG `full_fit` artifacts contain the whole-dataset bases and scalers consumed
by directed transfers. fMRI transfers consume its internal RRR artifact instead.
For fMRI, `cross_model_layer_per_layer` can replace `cross_model_layer` to run
each configured layer in a separate process and release memory between layers.

## 9. Run leave-one-subject-out RRR

```bash
for dataset in $PAPER_DATASETS; do
  make rrr DATASET="$dataset" RRR_MODE=leave_one_subject_out \
    MODELS="$PAPER_MODELS" CMD="uv run python"
done
```

This includes fMRI LOSO and the configured within-subject/PCA controls. The
Makefile launches one process per model layer for these runs.

## 10. Run all six directed cross-dataset RRR analyses

```bash
for target in $PAPER_DATASETS; do
  for source in $PAPER_DATASETS; do
    if [ "$target" = "$source" ]; then continue; fi
    make rrr DATASET="$target" RRR_MODE=cross_dataset SOURCE_DATASET="$source" \
      MODELS="$PAPER_MODELS" CMD="uv run python"
  done
done
```

The target dataset has its own significance selection; its transferred RRR/PCA
spaces and input scalers come from the completed source artifacts in step 8.

## 11. Run internal and directed language decoding

```bash
for target in $PAPER_DATASETS; do
  make language-decoding DATASET="$target" MODELS="$PAPER_MODELS" CMD="uv run python"
  for source in $PAPER_DATASETS; do
    if [ "$target" = "$source" ]; then continue; fi
    make language-decoding DATASET="$target" SOURCE_DATASET="$source" \
      MODELS="$PAPER_MODELS" CMD="uv run python"
  done
done
```

These commands use the checked-in task lists, RRR/PCA rank grids, and word-label
offsets `[-1, 0, 1]`. Directed decoding reads source fits directly and does not
need the cross-dataset RRR metric artifacts from step 10. fMRI decodes words by
default; `FMRI_TR_PRE_FIR=true` requests a separate optional TR-decoding analysis.

## 12. Check the complete matrix and export figures

```bash
uv run python -m scripts.utilities.check_rrr_results --results-root results
uv run python -m scripts.utilities.check_language_decoding_results --results-root results
uv run python notebooks/final_plots.py --output-dir figures
```

Resolve missing/incomplete results reported by the checks before treating the
figure export as complete. The export writes PDF, PNG, SVG, a significance
LaTeX table, and a result-gap report; existing export filenames are replaced.
Analysis artifacts live under `results/` and language labels under
`processed_data/`. Analysis configs normally use `refresh: false` to resume
existing artifacts; many preprocessing configs use `refresh: true`.

## Slurm execution

For steps 7–11, omitting `CMD="uv run python"` submits Slurm jobs. Submission
does not imply completion: wait for each prerequisite stage before submitting
consumers. `submit.sh` currently activates a site-specific `align_env`, calls
`module purge`, and requests a GPU and 64 GB RAM. Adapt its environment and
resource requests to your cluster before using Slurm; `uv sync` alone does not
create that named environment.

`make regenerate-transfer-results` is a Slurm-only alternative for step 8's
source fits, step 10, and step 11: it submits sources and all directed
RRR/decoding consumers with `afterok` dependencies, includes internal decoding,
and waits for the pipeline. It forces refresh and does not replace significance,
internal iEEG RRR evaluation, or LOSO. `make final-results` covers only a subset
of the result matrix and is not a complete reproduction command.
